DOCUMENTAÇÃO E EXPLICAÇÃO DO CÓDIGO - PAINEL IOT ARSENS (NEXT.JS + THINGSPEAK)
==============================================================================

Este arquivo explica o funcionamento de cada parte principal do projeto ARSENS, um painel
web de monitoramento de Monóxido de Carbono (CO), Temperatura e Umidade em tempo real.

- Local de medição: parada de ônibus "Atlantic Tower C/B", Av. Djalma Batista, Manaus/AM
  (coordenadas -3.10042, -60.02397 — via de alto tráfego).
- Hardware: ESP32 + sensor MQ-7 (CO) + sensor BME280 (temperatura e umidade).
- Nuvem: o ESP32 envia as leituras para o canal 3387680 do ThingSpeak.
- Painel: Next.js 16 (App Router), React 19, TypeScript, Tailwind CSS 4 e Recharts 3.

O site tem duas "personas":
- Painel público (rota /): para o cidadão comum. Tema claro, linguagem simples, sem login.
- Painel técnico (rota /dashboard): para pesquisadores. Tema escuro, gráficos, tabela e
  exportação de dados. Exige login.

1. ARQUITETURA E SEGURANÇA
--------------------------
Como o painel não possui um banco de dados tradicional (SQL/NoSQL), usamos "Variáveis de
Ambiente" (.env.local no computador, ou o painel de variáveis da Vercel em produção) para
armazenar informações sensíveis.

Variáveis utilizadas:
- THINGSPEAK_CHANNEL_ID      -> ID do canal no ThingSpeak (3387680).
- THINGSPEAK_READ_API_KEY    -> Chave de LEITURA do canal (o canal é privado).
- ADMIN_USER / ADMIN_PASS    -> Usuário e senha da tela de login.
- TELEGRAM_BOT_URL           -> Link do bot de alertas (https://t.me/MonitorCOESP32_789_bot).
- CO_CALIBRADO               -> "true" liga o semáforo do CO no painel público. Qualquer outro
                               valor (ou ausente) mostra "Sensor em calibração" (ver 5.8).

Essas variáveis são lidas apenas no servidor e nunca são enviadas ao navegador. O arquivo
.env.local NÃO vai para o GitHub (o .gitignore ignora arquivos .env*).

Importante: o painel usa somente a Read API Key. A Write API Key fica apenas no firmware do
ESP32 e nunca deve ser colocada no painel nem divulgada.

Separação Server x Client Components:
- Server Components (page.tsx, CoCard, MetricCard, LocationMap, DashboardHeader) rodam no
  servidor: buscam os dados e entregam o HTML pronto, sem enviar JavaScript extra.
- Client Components (marcados com "use client": ChartComponent, HistoryTable, RefreshButton,
  PublicRefresh)
  rodam no navegador porque precisam de interatividade (gráfico, chave liga/desliga, timer).
- O código que lê as chaves (lib/thingspeak.ts) só é importado por arquivos de servidor. Os
  componentes do navegador importam apenas lib/feed.ts e lib/co.ts, que não têm segredos.


2. FLUXO DE AUTENTICAÇÃO (LOGIN)
--------------------------------
- Arquivo: src/app/login/page.tsx
- Arquivo: src/app/actions.ts
- Arquivo: src/middleware.ts

* Como funciona:
Quando você acessa o site, o Next.js carrega o "middleware.ts". O papel do middleware é
interceptar as requisições. Se você tentar acessar "/dashboard" (ou qualquer sub-rota, como
"/dashboard/export") sem um "cookie" de sessão válido, ele te redireciona para "/login".
A raiz "/" (painel público) NÃO passa pelo middleware: qualquer pessoa pode abrir.
O botão "Acesso para Pesquisadores (Painel Técnico)" do painel público leva ao "/login";
se a pessoa já estiver logada, o middleware a manda direto para o "/dashboard".

Na tela de login você digita usuário e senha. Ao clicar em "Entrar no Painel", os dados são
enviados para o "actions.ts" (via Server Actions).

O "actions.ts" compara o que foi digitado com ADMIN_USER e ADMIN_PASS. Se bater, cria um
cookie seguro (httpOnly, válido por 1 dia) chamado "session" e redireciona para o painel
público ("/"). De lá, o botão "Acesso para Pesquisadores" abre o painel técnico direto, sem
pedir a senha de novo (a sessão já existe).
Se não bater, mostra "Credenciais inválidas. Tente novamente.". O botão "Sair" apaga o cookie
e volta para o painel público ("/").


3. O DASHBOARD E O THINGSPEAK
-----------------------------
- Arquivo: src/app/dashboard/page.tsx
- Arquivo: src/lib/thingspeak.ts

* Como funciona:
A página principal é um "Server Component": carrega os dados ANTES de enviar o HTML pronto.

Ao ser acessada, a função "getDashboardData()" faz DUAS requisições ao ThingSpeak ao mesmo
tempo (em paralelo):
  a) As últimas 20 leituras -> usadas nos cards e na tabela.
  b) As leituras das últimas 24 horas -> usadas no gráfico.

Ambas usam 'cache: "no-store"', ou seja, o Next.js NUNCA guarda esses dados em cache: toda
atualização busca os dados MAIS RECENTES do ThingSpeak.

Mapeamento dos campos do ThingSpeak:
- field1     -> Nível de CO (PPM)
- field2     -> Temperatura (°C)
- field3     -> Umidade (%)
- field4     -> Rs do sensor MQ-7 (Ω), dado de diagnóstico
- created_at -> Data/hora do registro (convertida para o fuso "America/Manaus").


4. REGRAS DE NEGÓCIO DOS DADOS
------------------------------
- Arquivo: src/lib/co.ts
- Arquivo: src/lib/feed.ts

4.1 Semáforo de Saúde do CO (faixas inspiradas nos padrões da EPA dos EUA para CO:
    9 ppm em média de 8 h e 35 ppm em média de 1 h):
    - Normal   (0 a 9 PPM)    -> ciano     (text-cyan-400)
    - Atenção  (10 a 35 PPM)  -> amarelo   (text-yellow-400)
    - Risco    (36 a 100 PPM) -> laranja   (text-orange-500)
    - Perigo   (acima de 100) -> vermelho piscando (text-red-500 + animate-pulse)
    - Simulação               -> roxo      (purple)

4.2 Modo Simulação (demonstração para a banca):
    O ESP32 envia o valor 999.90 quando o botão físico de teste é pressionado. Qualquer valor
    de CO maior ou igual a 999 é tratado como simulação:
    - No card de CO, o número é escondido ("---") e aparece a etiqueta roxa brilhante
      "Modo Simulação Ativo".
    - Na tabela, a linha recebe a etiqueta "Simulação".
    - No gráfico, o valor é ignorado para não distorcer a escala.

4.3 Leituras com erro:
    Valor 0.00 (ou vazio) em qualquer campo é considerado falha do sensor. A linha recebe o
    status "erro". Esses valores não entram nas médias do gráfico e podem ser ocultados na
    tabela.
    Essa regra vale só para CO, temperatura e umidade (field1 a field3). Rs (field4) vazio NÃO
    é considerado erro: as leituras antigas, anteriores ao firmware corrigido, não têm esse
    campo. Rs também não entra nas médias do gráfico.


5. COMPONENTES DA TELA
----------------------

5.1 Cabeçalho (src/components/DashboardHeader.tsx)
    - Logo e nome ARSENS.
    - Status de conexão: "Ao vivo" (ponto verde piscando) quando a última leitura tem menos de
      5 minutos; caso contrário, "Offline · há X min/h", indicando que o ESP32 parou de enviar.
    - Botão "Receber Alertas no Telegram", que abre o bot em nova aba.
    - Botões "Atualizar" e "Sair". Em telas pequenas os textos somem e ficam só os ícones.

5.2 Card de Nível de CO (src/components/CoCard.tsx)
    - Valor atual grande, com a cor do semáforo e etiqueta do nível (Normal, Atenção...).
    - Ícone "i": ao passar o mouse (ou focar pelo teclado) mostra uma explicação sobre o
      Índice de Qualidade do Ar e o aviso de que o MQ-7 dá leituras indicativas.
    - Seta de tendência: compara com a última leitura válida anterior.
      Vermelha para cima = o CO subiu; verde para baixo = o CO caiu.
    - Lógica do Modo Simulação (item 4.2).

5.3 Cards de Temperatura, Umidade e Resistência do Sensor (src/components/MetricCard.tsx)
    Temperatura em rosa, umidade em índigo e Rs em verde (emerald) — cores escolhidas de
    propósito para não se confundirem com as cores de alerta do semáforo.
    O card "Resistência do Sensor (Rs)" mostra o valor bruto do MQ-7 antes da conversão para
    ppm (legenda "Dado bruto do MQ-7 (diagnóstico)"): abaixo de 1.000 Ω em Ω (ex.: "980 Ω"),
    a partir de 1.000 Ω em kΩ com 1 casa decimal (ex.: "21,7 kΩ"); sem valor, "—".
    Os 4 cards ficam em 1 coluna no celular, 2×2 no tablet e lado a lado no computador.

5.4 Gráfico das últimas 24 h (src/components/ChartComponent.tsx)
    - Mostra CO, Temperatura e Umidade juntos. O CO usa o eixo da esquerda (ppm); temperatura e
      umidade usam o eixo da direita (0 a 100).
    - Para ficar leve, o servidor calcula a MÉDIA de cada janela de 10 minutos (no máximo
      144 pontos por dia) em vez de enviar milhares de leituras ao navegador.
    - Períodos em que o sensor ficou sem enviar dados aparecem como LACUNA (a linha é
      interrompida), em vez de "ligar os pontos" e inventar medições.
    - A legenda é clicável: cada série pode ser ligada/desligada.

5.5 Mapa do ponto de coleta (src/components/LocationMap.tsx)
    Mini-mapa do OpenStreetMap (gratuito, sem chave de API) com um pino na parada Atlantic
    Tower C/B. Recebe um filtro CSS para combinar com o tema escuro. O mapa é estático, para
    a rolagem da página não virar zoom; o link "Abrir mapa" abre a versão interativa.

5.6 Tabela de histórico (src/components/HistoryTable.tsx)
    - Lista as últimas 20 leituras com Data/Hora, CO, Temperatura, Umidade, Rs (kΩ) e Status.
    - A coluna Rs usa o mesmo formato do card (Ω ou kΩ); leituras antigas mostram "—".
    - O valor de CO de cada linha usa a cor do semáforo.
    - Chave "Ocultar leituras com erro" (ligada por padrão): esconde as linhas com 0.00.
      Desligada, elas aparecem apagadas com a etiqueta amarela "Erro".

5.7 Exportação CSV (src/app/dashboard/export/route.ts)
    Baixa até 8.000 leituras do ThingSpeak, para uso em pesquisas acadêmicas, em dois formatos:

    a) "Baixar Histórico (.xlsx)" — planilha do Excel gerada com a biblioteca "exceljs":
       - Colunas: Data | Hora | CO (ppm) | Temperatura (°C) | Umidade (%) | Rs (Ω) | Status
       - Rs (Ω) é um número inteiro real (formato "#,##0"), vazio quando não houver valor.
       - Larguras de coluna ajustadas, cabeçalho destacado e fixo ao rolar, e filtros prontos.
       - Datas e números são valores reais (não texto): dá para ordenar, filtrar e fazer
         gráficos direto no Excel. Horário de Manaus (UTC-4), 2 casas decimais.
       - Linhas de Erro ficam em amarelo claro e de Simulação em lilás. Nelas, o valor
         inválido fica em branco (999,90 é o botão de teste, não uma medição).
       - Uma segunda aba, "Sobre os dados", traz local, sensores, fuso e o significado dos
         status — útil para citar os dados em trabalhos acadêmicos. Também explica o Rs e a
         fórmula de conversão para ppm.

    b) "CSV padrão (Python/R)" — padrão internacional (",", decimal ".") com os dados brutos:
       data_hora_utc, data_hora_manaus, co_ppm, temperatura_c, umidade_pct, rs_ohm, status
       (rs_ohm é inteiro e fica vazio nas leituras antigas)

    A rota fica dentro de /dashboard, então também exige login.

5.8 Painel público do cidadão (src/app/page.tsx)
    Página inicial do site (rota /), aberta a todos, em tema claro e linguagem simples.
    - Busca só a leitura mais recente do ThingSpeak (results=1), para ficar leve: a página
      se atualiza a cada 15 s para cada visitante (componente PublicRefresh).
    - Card principal com o status do CO, usando as mesmas faixas do painel técnico (co.ts),
      traduzidas para "Qualidade Boa" (verde), "Atenção" (amarelo), "Risco Moderado"
      (laranja) e "Perigo" (vermelho), com uma orientação para quem está no ponto. O valor em
      ppm aparece pequeno, em segundo plano.
    - Estados especiais: "Modo de Demonstração" (botão de teste, 999,90), "Sem leitura no
      momento" (sem valor válido) e aviso de dados desatualizados (mais de 5 min sem envio).
    - "Sensor em calibração": enquanto CO_CALIBRADO não for "true", o semáforo fica pausado
      e o valor de CO não é exibido, para não alarmar o público com leituras ainda não
      calibradas. Temperatura e umidade continuam aparecendo. Para ativar o semáforo depois
      de calibrar o R0: cadastrar CO_CALIBRADO=true na Vercel e fazer Redeploy.
    - Temperatura e umidade (o Rs não aparece: é dado técnico).
    - Blocos de contexto (o ponto de ônibus em frente ao Millennium Shopping, ao lado da
      Uninorte, e o efeito do tráfego de ônibus no ar de quem espera) e educativo (o que é o
      CO e seus efeitos), com links para a EPA e para as diretrizes da OMS (2021).
    - Botão "Acesso para Pesquisadores (Painel Técnico)", que leva ao login. No painel
      técnico, o botão com ícone de casa ("Voltar ao Modo Simples") volta para a raiz.


6. ATUALIZAÇÃO DOS DADOS (MANUAL E AUTOMÁTICA)
----------------------------------------------
- Arquivo: src/app/dashboard/RefreshButton.tsx

* Como funciona:
O componente usa a função "router.refresh()" do Next.js, que pede ao servidor para rodar de
novo a busca no ThingSpeak e atualizar a página SEM recarregá-la (sem piscar a tela e sem
perder o estado, como a chave da tabela ou as séries escolhidas no gráfico).

- Automática: um "useEffect" cria um timer que chama router.refresh() a cada 15 segundos.
  Para economizar requisições, a atualização só acontece com a aba visível.
- Manual: o botão "Atualizar" faz o mesmo na hora; o ícone gira enquanto a atualização ocorre.


7. DESIGN E ESTILOS (TAILWIND CSS)
----------------------------------
Toda a parte visual é feita com Tailwind CSS, colocando as classes direto no className.

Identidade visual ("Central de Comando / Telemetria"):
- Fundo slate-900, cards em slate-800 com bordas slate-700.
- Fonte Inter, com hierarquia forte: rótulos pequenos em cinza claro e valores grandes em
  negrito.
- Layout responsivo: os cards se reorganizam em 1, 2 ou 4 colunas conforme a largura da
  tela; gráfico e mapa ficam lado a lado no computador e empilhados no celular; a tabela
  rola na horizontal em telas estreitas.


8. COMO RODAR LOCALMENTE
------------------------
1. Instalar o Node.js (versão LTS).
2. Criar o arquivo .env.local na raiz do projeto com as variáveis do item 1.
3. No terminal, dentro da pasta do projeto:
     npm install
     npm run dev
4. Abrir http://localhost:3000 (painel público). Para o painel técnico, clicar em
   "Acesso para Pesquisadores" e entrar com ADMIN_USER e ADMIN_PASS.

Em produção (Vercel), cadastre as mesmas variáveis em Settings > Environment Variables,
usando uma senha forte (diferente da usada nos testes locais).


9. PONTOS DE ATENÇÃO E MELHORIAS FUTURAS
----------------------------------------
- Calibração do MQ-7: as leituras anteriores a 17/10/2026 (~440 ppm) são inválidas.
  O ADC do ESP32 estava configurado com atenuação de 0 dB e saturava no valor máximo,
  e a conversão para ppm era linear. O firmware foi corrigido: atenuação de 11 dB,
  cálculo da resistência do sensor (Rs = RL × (Vc − V_A0) / V_A0, com RL efetivo
  considerando o divisor de tensão), aquecimento por PWM com tensão RMS correta
  (1,4 V), leitura no fim da fase de baixa temperatura e conversão pela curva
  logarítmica do datasheet (PPM = 99,042 × (Rs/R0)^−1,518). R0 é obtido por calibração
  em ar limpo após 48 h de pré-aquecimento. Abaixo de ~20 ppm as leituras são
  indicativas, por estarem abaixo da faixa especificada do sensor. Os valores
  continuam sendo indicativos, não certificados.
- O Next.js 16 avisa que o arquivo "middleware.ts" foi renomeado para "proxy.ts". O código
  atual ainda funciona, mas a migração é recomendada.
- O "npm run lint" aponta um uso de "any" em src/app/actions.ts (tipagem a melhorar).


RESUMO DO FLUXO
---------------
1. O ESP32 mede CO, temperatura e umidade e envia ao ThingSpeak.
2. O cidadão abre o site (/) e vê o status do ar em linguagem simples, sem login.
3. O pesquisador digita a senha; o actions.ts valida e cria um cookie.
4. Após o login, ele volta ao painel público; ao clicar em "Acesso para Pesquisadores",
   o middleware.ts o deixa entrar no /dashboard.
5. O dashboard/page.tsx busca no ThingSpeak, no servidor, as últimas 20 leituras e as 24 h.
6. As regras (semáforo, simulação, erro) são aplicadas e a tela é montada.
7. A cada 15 s as duas páginas se atualizam sozinhas, sem recarregar.
8. Pesquisadores podem baixar o histórico completo (.xlsx ou CSV).
